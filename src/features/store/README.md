# store
메인 홈(가게 목록 = "매장 찾기") 화면을 담당하는 폴더입니다. 매장 목록은 `storeApi.js`를 통해 불러오고, 헤더의 로그인 상태는 `src/store/authStore.js`(Zustand)에서 읽습니다.

> 담당: Part A 전승호

---

## ⚠️ 현재 데이터 연동 상태

- **매장 목록은 실제 백엔드 API(`GET /api/stores`)를 호출합니다.** (`storeApi.js`의 `USE_DUMMY = false`)
- **검색·카테고리 필터·페이지네이션을 모두 서버에서 처리합니다.** 화면은 한 페이지(8개)만 받아 그립니다.
  - 요청: `GET /api/stores?keyword=&category=&page=&size=8` (Spring 페이지 번호는 0부터 → 화면 1페이지 = `page=0`)
  - 응답: **페이지 객체** — 매장 배열은 `content` 안에 있고, `totalElements`·`totalPages`·`number`·`size` 등 페이지 정보는 응답 최상위에 옴 (실제 호출로 확인)
- 백엔드 없이 테스트하려면 `USE_DUMMY`를 `true`로 바꾸면 `dummyStores.js`의 매장 30개를 서버와 같은 모양(검색·카테고리·페이지 적용)으로 0.4초 뒤에 돌려줍니다.

## 메인 홈 화면 — `StoreListPage.jsx` (`/`)

### 헤더 (스크롤해도 상단 고정)
| 위치 | 내용 |
|---|---|
| 왼쪽 | 로고 이미지 (공용 `Logo` 컴포넌트, 클릭 시 `/`) |
| 가운데 | 매장명 검색창 (최대 640px, 항상 헤더 정중앙) |
| 오른쪽 | 로그인 전: "로그인" 버튼 → `/login` / 로그인 후: "OOO님" · 마이페이지 아이콘 · "로그아웃" 버튼 |

- 마이페이지 아이콘은 아직 경로 연결 전 — 클릭 시 콘솔 로그만 출력
- "로그아웃"은 `authStore.logout()`을 호출하고 메인 홈에 그대로 머묾
- 이 헤더는 메인 홈 전용입니다 (별도 공용 헤더 컴포넌트 아님)

### 본문
- **안내 배너(히어로)**: 소개글 → 제목(2줄) → 설명글 3단 구조
  | 줄 | 문구 |
  |---|---|
  | 소개글 | 스마트 픽업 주문 서비스 |
  | 제목 | 동네 단골 매장의 갓 만든 메뉴를 / 기다림 없이 바로 픽업하세요! |
  | 설명글 | 주문 후 픽업 시간에 맞춰 방문하시면, 갓 준비된 메뉴를 바로 받아가실 수 있어요. |
- **카테고리 탭**: 전체 / 베이커리 / 카페 / 분식 / 일식 / 치킨 (백엔드 매장 카테고리 값과 동일, `StoreListPage.jsx`의 `CATEGORIES`)
- **결과 개수**: "가게 N곳" (서버 응답의 `totalElements` — 검색·카테고리 적용 후 전체 개수)
- **가게 카드 그리드**: 카드 최소 폭 300px, 화면 폭에 따라 4열(1324px~) · 3열 · 2열(684~1003px) · 1열(~683px)
- **페이지네이션**: 목록 아래 "이전 · 페이지 번호 · 다음" 버튼

### 검색 · 카테고리 필터 · 페이지네이션 (서버 처리)
| 기능 | 동작 |
|---|---|
| 검색 | 매장명 부분 일치, 앞뒤 공백 무시. **디바운스**: 타이핑이 0.3초(`SEARCH_DELAY`) 멈추면 검색어를 확정해 서버에 `keyword`로 요청 |
| 검색 + 카테고리 | 두 조건을 **모두 만족**하는 매장만 표시 (선택한 카테고리 탭 안에서 검색). 맞는 매장이 없으면 "조건에 맞는 가게가 없어요" |
| 카테고리 필터 | 선택한 카테고리를 서버에 `category`로 요청 (`전체`면 파라미터 없이 요청) |
| 페이지네이션 | **페이지당 8개**(`PAGE_SIZE`)씩 서버가 잘라서 응답. 페이지 버튼 수는 응답의 `totalPages`. 현재 백엔드 매장 30개 기준 4페이지(8·8·8·6) |
| 1페이지로 돌아가는 경우 | 검색어 확정, 카테고리 변경, "전체 가게 보기" 클릭 |
| 페이지 이동 시 | 화면 맨 위로 부드럽게 스크롤 |
| 버튼 표시 | 결과가 1페이지 이하이면 페이지 버튼을 숨김. 첫 페이지에서 "이전", 마지막 페이지에서 "다음"은 비활성화 |

- **상태 구조**: `keyword`(입력칸에 바로 보이는 값)와 `searchKeyword`(0.3초 뒤 확정되어 서버로 보내는 값)를 나눠 관리
- **요청 시점**: 확정된 검색어·카테고리·페이지가 바뀔 때마다 요청. 검색어 확정과 1페이지 이동은 한 번에 바뀌어 요청은 1번만 나감
- **늦게 온 응답 무시**: 요청 조건(`검색어|카테고리|페이지`)을 응답과 함께 저장해, 현재 조건과 다르면 로딩으로 판단 → 빠르게 조건을 바꿔도 옛날 응답이 화면을 덮지 않음
- 디바운스는 실습 코드의 `useEffect` 안 `setTimeout` + 정리 함수 `clearTimeout` 패턴과 같음
- 영문 매장명 검색은 **대소문자를 구분**함 (백엔드가 `LIKE` 그대로 비교, 한글 매장명은 영향 없음)

### 상태 처리
| 상태 | 표시 |
|---|---|
| 로딩 중 | 회색 카드 틀(스켈레톤) 8개(`SKELETON_COUNT` = 한 페이지 개수) + 반짝임 효과 |
| 불러오기 실패 | "가게 목록을 불러오지 못했습니다." + "다시 시도" 버튼 |
| 결과 없음 | "조건에 맞는 가게가 없어요" + "전체 가게 보기" 버튼 (검색어·카테고리 초기화) |

### 이동
- 가게 카드(또는 "가게 상세보기" 버튼) 클릭 → `/stores/{storeId}` (파트 B 매장 상세 화면)

## 가게 카드 — `StoreCard.jsx`

### Props
| Prop | 타입 | 용도 |
|---|---|---|
| `store.id` | `number` | 클릭 시 `onClick`에 전달 |
| `store.name` | `string` | 가게명 (1줄, 넘치면 `...`) |
| `store.category` | `string` | 카테고리 뱃지 |
| `store.address` | `string` | 주소 (핀 아이콘) |
| `store.openTime` / `store.closeTime` | `string \| null` | 백엔드는 `'HH:mm:ss'` → 화면엔 `'HH:mm'`으로 변환해 표시 + 영업 상태 계산. 없으면 "영업시간 정보 없음" |
| `store.imageUrl` | `string?` | 대표 이미지 URL — 없거나 로딩에 실패하면 회색 대체 박스 |
| `store.description` | `string?` | 한 줄 소개 — 있을 때만 표시 (백엔드 응답엔 없음) |
| `onClick` | `(storeId: number) => void` | 카드 또는 "가게 상세보기" 버튼 클릭 시 호출 |

### 카드 구성
- **이미지**: 항상 3:2 비율. `imageUrl`이 없거나(`null`) 로딩에 실패하면 같은 비율의 회색 박스 + 이미지 아이콘으로 대체
- **영업 상태 뱃지**: 현재 시각과 영업시간을 비교해 "주문 가능" / "준비 중" 표시 (마감이 자정을 넘기는 경우도 처리, 영업시간 정보가 없으면 "준비 중")
  - 별도 상태 필드는 없고 `openTime`·`closeTime`만으로 계산 (`isOpenNow`)
  - 시작 시각은 포함, 마감 시각은 제외 — 09:00~21:00 매장은 09:00 "주문 가능", 21:00 정각 "준비 중"
  - 시작·마감이 같은 값이면 항상 "준비 중"
  - 기준 시각은 서버가 아니라 **사용자 PC(브라우저)의 시계·시간대**
- 가게명(1줄 전체 폭) → 카테고리 뱃지 + 한 줄 소개 → 영업시간(시계 아이콘) → 주소(핀 아이콘) → "가게 상세보기" 버튼
- 모든 텍스트 줄을 1줄로 고정해 가게명 길이·소개 유무·이미지 유무와 관계없이 **카드 높이가 항상 같음**

## 데이터 — `storeApi.js` · `dummyStores.js`

### `getStores({ keyword, category, page, size })`
| 인자 | 의미 |
|---|---|
| `keyword` | 매장명 검색어. 비어 있으면 파라미터를 보내지 않음 |
| `category` | 카테고리. `전체`나 빈 값이면 파라미터를 보내지 않음 |
| `page` | **화면 기준 1부터** — 서버에는 `page - 1`로 보냄 |
| `size` | 한 페이지 개수 (`StoreListPage`의 `PAGE_SIZE` = 8) |

- 반환: `{ content, totalElements, totalPages }` (값이 없으면 빈 배열·0)
- `USE_DUMMY = false`(현재) → `GET /api/stores?keyword=&category=&page=&size=` 호출
- `USE_DUMMY = true` → 0.4초 기다린 뒤 `DUMMY_STORES`에 검색·카테고리를 적용하고 한 페이지만 잘라서 같은 모양으로 반환

### 더미 매장 30개
- 필드: `id`, `name`, `category`, `address`, `storePhone`, `openTime`, `closeTime`, `description`, `imageUrl` (평점·리뷰수 필드는 삭제 — 이번 프로젝트 범위에 리뷰 기능 없음)
- **`imageUrl`은 30개 모두 `null`** — 이미지가 없을 때 카드의 대체 박스 처리를 확인하기 위함
- 카테고리 분포: 베이커리 6 · 카페 6 · 분식 6 · 일식 6 · 치킨 6 (백엔드 카테고리 값과 동일)
- id 1은 1차 기획 문서의 `dummy_data.sql` 1번 매장 값을 옮긴 것, id 2~30은 필터·페이지네이션 테스트용 가상 매장
- 테스트용 특수 매장: id 12(가게명·주소가 아주 긴 경우 말줄임 확인), id 19·29(18:00~02:00·17:00~01:00, 자정을 넘기는 영업시간 확인)

## 스타일

### 디자인 방향
- **무채색(흰색·회색·검정) + 포인트 컬러 하나**로 구성 (로그인·회원가입 화면과 같은 방식)
- 팀 공통 루트 변수(`src/index.css`의 `--accent`, `--bg` 등)는 쓰지 않고, `StoreListPage.module.css`의 `.page`에 정의한 **로컬 변수 `--home-*`**만 사용
- `StoreCard.module.css`, `CategoryFilter.module.css`도 이 `--home-*` 변수를 사용 → 두 컴포넌트는 메인 홈 페이지 안에서 렌더링된다는 전제
- 루트 파일(`index.css`, `App.jsx`, `App.css`)은 수정하지 않음

### 포인트 컬러
| 변수 | 값 | 쓰는 곳 |
|---|---|---|
| `--home-accent` | `#ed5821` (색조 16° · 채도 85% · 명도 53%) | 선택된 카테고리 칩, 현재 페이지 번호, "가게 상세보기" 버튼, 헤더 "로그인"/"로그아웃" 버튼 |
| `--home-on-accent` | `#ffffff` | 위 요소들의 글자, 배너 글자 |

- `AuthForm.module.css`의 `--auth-accent`와 같은 값
- 포인트 컬러 버튼은 마우스를 올리면 살짝 어두워짐(`brightness(0.92)`)
- 흰 글자와의 대비는 3.49:1 (큰 글자 기준 3:1은 넘고, 본문 기준 4.5:1은 미달)

### 안내 배너 그라데이션
| 변수 | 값 | 흰 글자 대비 |
|---|---|---|
| `--home-hero-from` | `var(--home-accent)` = `#ed5821` (왼쪽 위) | 3.49:1 |
| `--home-hero-to` | `#ff8f66` (오른쪽 아래, 색조 16° · 채도 100% · 명도 70%) | 2.24:1 |

- 135° 대각선 그라데이션으로, 왼쪽은 진하고 오른쪽으로 갈수록 밝아짐
- 소개글·제목·설명 글자는 흰색. 글자는 배너 왼쪽(진한 쪽)에 놓임
- `--home-hero-from`은 `--home-accent`를 따라가므로 포인트 컬러를 바꾸면 배너 시작 색도 같이 바뀜 (끝 색은 따로 지정)

### 안내 배너 글자 · 여백
| 요소 | 데스크톱 | 640px 이하 |
|---|---|---|
| 배너 안쪽 여백 (상하 · 좌우) | `30px 40px` | `20px 22px` |
| 소개글 `.eyebrow` | 15px · 굵기 700 · 줄높이 1.3 · 아래 간격 8px | 13px · 아래 간격 6px |
| 제목 `.title` (h1) | 36px · 굵기 800 · 줄높이 1.32 | 24px |
| 설명글 `.subtitle` | 17px · 줄높이 1.4 · 위 간격 12px | 14px · 위 간격 8px |

- 글자 크기 비율(소개글 : 제목 : 설명글 ≈ 1 : 2.4 : 1.15)은 팀 디자인 참고 이미지 기준
- 제목 줄바꿈은 `<br />`로 고정 (좁은 화면에서는 각 줄이 추가로 줄바꿈될 수 있음)

### 시그널 컬러 (의미 전달용으로 그대로 유지)
| 색 | 쓰는 곳 |
|---|---|
| 초록 `rgba(34, 160, 90, 0.9)` | 카드 "주문 가능" 뱃지 |
| 회색 `rgba(60, 60, 70, 0.75)` | 카드 "준비 중" 뱃지 |

### 그 밖의 요소

### 다크모드
- **현재 OS 설정과 관계없이 라이트 모드로 고정**
- 다크모드용 변수 값은 삭제하지 않고 `StoreListPage.module.css`의 `[비활성] 다크 모드` **주석 블록으로 보관** → 다시 쓰려면 주석을 풀고, 같은 파일의 `color-scheme: light` 한 줄도 지워야 함
- 라이트 고정을 위해 이 파일 안에서 막은 것
  - 루트 `color-scheme: light dark` 때문에 스크롤바·검색창 지우기(×) 버튼이 어둡게 그려지는 문제 → 메인 홈이 떠 있을 때만 `color-scheme: light`
  - 루트의 `h1` 색 규칙·글자색 상속 → 제목과 `.page`에 글자색 직접 지정
  - 버튼·링크의 브라우저 기본 파란 포커스 테두리 → 무채색 테두리로 통일

### 레이아웃
- 최상위 `.page`는 `width: 100vw; margin-left: calc(-50vw + 50%)`로 공용 `#root`(최대 1126px) 박스를 벗어나 화면 전체 폭 사용. 가로 스크롤은 `:global(html):has(.page)`에 `overflow-x: clip`을 넣어 메인 홈이 떠 있을 때만 막음
- 콘텐츠 최대 너비 1400px(`--content-max`), 좌우 여백 32px(`--gutter`)
- 헤더 로고: 높이 60px (640px 이하 52px). `logo.svg` 안쪽 빈 여백만큼 음수 margin으로 상쇄해 로고를 키워도 헤더 높이는 그대로
- 화면 너비 640px 이하: 좌우 여백 16px, 헤더 2줄(1줄: 로고 · 메뉴 / 2줄: 검색창 전체 폭), "OOO님" 숨김, 배너 글자·여백 축소(위 표 참고)
