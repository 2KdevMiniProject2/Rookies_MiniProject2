## 1. 프로젝트 기본 철학: "배운 범위 안에서 탄탄하게!"

> ⚠️ **핵심 원칙: 오버엔지니어링(너무 어렵고 복잡한 기술) 금지!**  
> 이번 프로젝트는 화려하고 어려운 외부 라이브러리를 쓰는 것이 아니라, **지금까지 수업에서 배운 백엔드(Spring Boot/JPA/Security)와 프론트엔드(React/Vite/Zustand)의 핵심 기본기를 충실히 구현하고 팀워크를 발휘하는 것**이 평가의 핵심입니다.

---

## 2. 🚫 쓰지 않는 어려운 기술 vs ⭕ 우리가 쓰는 배운 기술 매핑

| 기능 영역 | 🚫 쓰지 않는 어려운 기술 (오버엔지니어링) | ⭕ 우리가 쓰는 배운 기술 (추천 & 채택) |
| :--- | :--- | :--- |
| **실시간 주문 알림** | WebSocket, STOMP, Kafka, RabbitMQ | **5초 주기 자동 조회 (React `setInterval` Polling)** 또는 [새로고침] 버튼 |
| **결제 시스템** | 토스페이먼츠, 카카오페이 등 실제 PG사 연동 | **모의 주문/결제** (`[주문하기]` 클릭 시 즉시 DB에 `PENDING` 저장) |
| **이미지 파일 저장** | AWS S3 버킷, CloudFront 연동 | **이미지 URL 링크 입력 방식** (Unsplash 등) 또는 기본 로컬 정적 파일 |
| **인증/인가** | OAuth2 소셜 로그인 (카카오/구글), Redis 세션 | 수업에서 배운 **Spring Security + JWT Bearer Token** 기본 구현 |
| **상태 관리** | Redux, Redux-Saga, MobX | 수업 템플릿에 세팅된 가볍고 직관적인 **Zustand** |
| **스타일링** | 복잡한 외부 UI 프레임워크 (Tailwind 설정 충돌 등) | 가볍고 제약 없는 **Vanilla CSS / CSS Modules** |

## 3. 💯 평가 배점표 (100점 만점) 공략 체크리스트

### 3.1 기본 구현 영역 (70점)

#### 🟢 BackEnd (35점)
* [ ] **Entity 및 Repository 구현 (10점)**
  * `@ManyToOne`, `@OneToMany` 연관관계 매핑의 정확성
  * `@Column(nullable = false)`, `@NotNull`, 길이 제한 등 적절한 제약조건 설정
* [ ] **Service 및 비즈니스 로직 (10점)**
  * 데이터 정합성 검증: 장바구니 주문 시 가격 위변조 검증 로직
  * 트랜잭션 처리: 주문 생성 시 `@Transactional` 반드시 적용
  * 예외 처리: `@RestControllerAdvice`로 일관된 에러 JSON 응답 반환
* [ ] **REST API 구현 (10점)**
  * HTTP 메서드(GET, POST, PATCH 등) 적절한 사용
  * 일관된 응답 DTO (`success`, `data`, `message`) 사용
* [ ] **Spring Security 구현 (5점)**
  * JWT 토큰 발급 및 필터 구현, 역할별 접근 인가 (`CUSTOMER` vs `OWNER`)

#### 🔵 FrontEnd (35점)
* [ ] **React 컴포넌트 구조 (10점)**
  * 단일 책임 원칙에 따른 컴포넌트 분리 (`StoreCard`, `MenuItemCard` 등)
  * 명확한 Props 전달 및 상태 분리
* [ ] **UI/UX 구현 (10점)**
  * 피그마 와이어프레임 준수, 직관적이고 깔끔한 반응형 레이아웃
  * 로딩 상태 및 빈 데이터(Empty State) 안내 처리
* [ ] **API 연동 (10점)**
  * `src/api/client.js` Axios 인스턴스를 통한 표준 통신
  * 에러 발생 시 사용자 친화적인 alert/토스트 메시지 표시
* [ ] **권한별 화면 라우팅 (5점)**
  * `ProtectedRoute.jsx`를 활용한 손님/사장님 페이지 접근 제어

---

### 3.2 추가 구현 영역 (가산점 15점)
수업에서 배운 고급 기법으로 15점 만점을 확보합니다.

* [ ] **JPA 성능 튜닝: N+1 문제 해결 (5점)**
  * 매장 목록 조회 시 매장 상세(`StoreDetail`)를 조회할 때 또는 주문 상세(`OrderItem`) 조회 시 **`join fetch`** 또는 `@EntityGraph` 적용!
* [ ] **상태 관리 라이브러리 활용 (5점)**
  * 수업 템플릿의 **Zustand**(`authStore`, `cartStore`)를 활용하여 새로고침/페이지 이동 간 데이터 보존
* [ ] **페이징 및 검색/필터 기능 (3점)**
  * Spring Data JPA `Pageable` 또는 메인 홈 카테고리 필터링 쿼리 적용
* [ ] **파일 또는 이미지 관리 (2점)**
  * 매장/메뉴 등록 시 대표 이미지 URL 관리
