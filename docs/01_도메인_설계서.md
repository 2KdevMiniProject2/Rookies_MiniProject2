# 📋 [루키즈 미니프로젝트 2] 01. 도메인 설계서

---

## 1. 도메인 개요 (Domain Overview)

본 프로젝트는 동네 소상공인(베이커리, 카페, 음식점 등)과 지역 주민(손님)을 실시간으로 연결하는 **"소상공인 픽업 주문 및 매장 관리 플랫폼"**입니다.
* **고객 관점**: 대기 시간 없이 원하는 시간에 메뉴를 포장/픽업할 수 있도록 간편하게 주문하고, 조리 진행 상태를 실시간으로 확인합니다.
* **사장님 관점**: 키오스크나 복잡한 POS 장비 없이도 웹 브라우저를 통해 매장 정보, 메뉴 품절 관리, 주문 접수/조리완료 상태 변경 및 당일 매출을 효율적으로 관리합니다.

---

## 2. 용어 정의 (Glossary)

팀원 간 커뮤니케이션과 코드 명명 규칙의 통일을 위해 아래 용어를 표준으로 정의합니다.

| 용어 (한글) | 영문 명칭 | 설명 |
| :--- | :--- | :--- |
| **회원** | `User` | 시스템을 이용하는 모든 사용자 (손님 또는 사장님) |
| **권한/역할** | `Role` | 회원 유형 (`ROLE_CUSTOMER`: 손님, `ROLE_OWNER`: 사장님, `ROLE_ADMIN`: 관리자) |
| **가게 / 매장** | `Store` | 사장님이 운영하는 등록된 사업장 (이름, 주소, 카테고리 등) |
| **가게 상세** | `StoreDetail` | 영업시간, 휴무일, 매장 전화번호, 상세 소개글 등 부가 정보 |
| **메뉴 항목** | `MenuItem` | 매장에서 판매하는 개별 상품 (상품명, 가격, 사진, 품절 여부) |
| **주문** | `Order` | 고객이 특정 매장의 메뉴들을 픽업 목적으로 결제/신청한 주문 건 |
| **주문 상세** | `OrderItem` | 하나의 주문에 포함된 개별 메뉴와 수량, 주문 시점의 결제 단가 |
| **주문 상태** | `OrderStatus` | 주문의 생명주기 (`PENDING` ➔ `ACCEPTED` ➔ `COMPLETED` / `CANCELLED`) |
| **픽업 시간** | `PickupTime` | 고객이 매장을 직접 방문하여 상품을 수령하기로 지정한 시간 |

## 3. 핵심 도메인 객체 (Core Domain Objects)

### 1) 회원 (`User`)
* 시스템에 가입된 주체로, 이메일과 비밀번호로 인증합니다.
* `role`을 통해 일반 고객(손님)인지 매장 점주(사장님)인지 구분합니다.

### 2) 가게 (`Store`) & 가게 상세 (`StoreDetail`)
* 사장님(`User`)에 의해 생성 및 소유됩니다.
* 카테고리(카페/디저트, 베이커리, 한식 등)별로 분류되며 메인 홈 목록에 노출됩니다.
* 영업시간(오픈/마감) 및 안내 문구를 포함합니다.

### 3) 메뉴 항목 (`MenuItem`)
* 특정 가게(`Store`)에 종속된 판매 품목입니다.
* 사장님이 실시간으로 `is_sold_out`(품절) 여부를 토글할 수 있습니다.

### 4) 주문 마스터 (`Order`) & 주문 상세 (`OrderItem`)
* 고객(`User`)이 특정 매장(`Store`)에 대해 발행하는 픽업 요청입니다.
* 총 주문 금액, 픽업 희망 일시, 고객 요청사항, 주문 상태를 보유합니다.
* 주문 당시의 가격 변동에 영향을 받지 않도록 `OrderItem`에 주문 시점 단가를 스냅샷으로 보관합니다.

## 5. 핵심 비즈니스 규칙 (Business Rules)

### 🟢 [파트 A] 회원 및 가게 관리 규칙
1. **이메일 고유성**: 시스템 내 이메일은 중복될 수 없습니다 (`unique = true`).
2. **사장님 1인 1가게 원칙**: MVP 단계에서는 사장님(`ROLE_OWNER`) 1명당 1개의 매장만 등록/관리할 수 있습니다.
3. **가게 노출 조건**: 정상적으로 영업 정보(가게 이름, 카테고리, 주소)가 등록된 가게만 메인 홈 목록에 조회됩니다.

### 🟡 [파트 B] 메뉴 및 주문 생성 규칙
1. **단일 매장 주문**: 하나의 주문(`Order`)에는 **동일한 매장(`Store`)의 메뉴만** 담을 수 있습니다. (다른 매장 메뉴를 담으려 할 경우 장바구니 초기화 안내)
2. **품절 메뉴 주문 불가**: `isSoldOut == true`인 메뉴는 장바구니에 담거나 주문서에 포함하여 결제할 수 없습니다.
3. **주문 금액 일치 검증**: 클라이언트에서 전달한 `totalAmount`는 백엔드에서 `(각 메뉴 가격 * 수량)`의 합과 반드시 일치해야 합니다. (위변조 방지)
4. **픽업 시간 유효성**: 픽업 희망 시간은 매장의 영업시간(오픈~마감) 내여야 하며, 현재 시간보다 이후여야 합니다.

### 🔴 [파트 C] 주문 상태 전환 및 매출 집계 규칙
1. **상태 전환 라이프사이클**:
   * `PENDING` (접수 대기) ➔ 사장님 수락 시 ➔ `ACCEPTED` (조리중)
   * `ACCEPTED` (조리중) ➔ 사장님 조리 완료 시 ➔ `COMPLETED` (픽업 대기/완료)
   * `PENDING` 상태에서는 사장님이 주문을 `CANCELLED` (거절/취소) 할 수 있습니다.
   * `COMPLETED` 상태로 변경된 이후에는 상태를 되돌릴 수 없습니다.
2. **매출 집계 기준**:
   * "오늘의 총 매출액"은 주문 상태가 `ACCEPTED` 또는 `COMPLETED`인 건들의 `totalAmount` 합계(`SUM`)로 계산합니다. (취소/대기 건 제외)
