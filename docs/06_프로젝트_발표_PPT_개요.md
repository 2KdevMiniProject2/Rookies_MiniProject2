## 2. 슬라이드별 구성 목차 (총 10~12장)

### Slide 1: 표지 (Cover)
* **내용**: 
  * 프로젝트명: 동네 소상공인을 위한 스마트 픽업 주문 플랫폼 - **루키즈 오더 (Rookies Order)**
  * 팀명 및 팀원 소개 (승호, 현준, 영서, 인선, 본영, 지우)

### Slide 2: 기획 배경 및 문제 정의 (Background)
* **내용**:
  * 소상공인 점주의 페인포인트: 높은 배달앱 수수료 및 복잡한 키오스크 비용 부담
  * 지역 손님의 페인포인트: 바쁜 출퇴근/점심시간 매장 대기 시간 발생
  * 해결책: 웹 브라우저 하나로 끝내는 가볍고 직관적인 모바일 웹 픽업 주문 및 주문 관리 시스템

### Slide 3: 팀 빌딩 및 역할 분담 (Team Architecture)
* **내용**: 식당 비유 구조도
  * 🏠 **파트 A (가게 세우기)**: 회원 인증 & 매장 목록 (승호 FE / 현준 BE)
  * 🍔 **파트 B (메뉴 & 주문)**: 메뉴판 & 장바구니 픽업 주문 (영서 FE / 인선 BE)
  * 🔔 **파트 C (주방 & 카운터)**: 실시간 주문 접수 & 매출 대시보드 (본영 FE / 지우 BE)

### Slide 4: 협업 전략 (병렬 독립 개발 치트키)
* **내용**:
  * 타 파트 작업 대기로 인한 병목 제거
  * `store_id` (가게 1번) & `order_id` (주문 5001번) 더미 데이터 주입을 통한 3개 파트 동시 개발 성공기

### Slide 5: 시스템 아키텍처 및 기술 스택 (Architecture)
* **내용**:
  * FE: React 19, Vite, Zustand, Axios, Vanilla CSS
  * BE: Spring Boot, Spring Data JPA, Spring Security, JWT, MySQL
  * 배포/환경: 로컬 개발 환경 및 분리 브랜치 협업 전략

### Slide 6: ERD 및 데이터 모델링 (Data Modeling)
* **내용**:
  * 6개 핵심 엔티티 (`User`, `Store`, `StoreDetail`, `MenuItem`, `Order`, `OrderItem`)
  * 도메인 간 결합도를 낮추고 데이터 일관성을 지키는 연관관계 및 인덱스 설계

### Slide 7~9: 핵심 기능 시연 (Live Demo / Screenshot)
* **Slide 7 (파트 A)**: 회원가입, 손님/사장님 모의 로그인, 메인 홈 가게 카드 탐색
* **Slide 8 (파트 B)**: 특정 매장 상세 진입 ➔ 메뉴 `+ 담기` ➔ 장바구니 ➔ 픽업 시간 지정 주문
* **Slide 9 (파트 C)**: 사장님 카운터 실시간 주문 접수(`[수락]` ➔ `[조리완료]`), 오늘 매출 통계 확인

### Slide 10: 기술적 도전 및 해결 과정 (Engineering Challenges)
* **내용**:
  * **JPA N+1 문제 해결**: 매장 목록 및 주문 상세 조회 시 `Fetch Join` 또는 `@EntityGraph` 적용
  * **주문 금액 위변조 방지**: 클라이언트 계산값과 서버 단가 합산값 정합성 검증 로직
  * **실시간성 확보**: 효율적인 주문 상태 폴링 및 낙관적 UI 렌더링

### Slide 11: 향후 개선 과제 및 확장성 (Future Work)
* **내용**:

  * 사장님 일간/주간 매출 분석 차트 기능
