## 3. 파트별 세부 목표 및 개발 스코프

### 🟢 파트 A: "회원 & 가게 목록" (가게 세우기)
* **목표**: 손님/사장님이 로그인하고, 메인 홈에서 동네 매장들을 탐색하며, 사장님이 내 가게를 등록/수정한다.
* **BE 개발 범위**:
  * 테이블: `users` (회원), `stores` (가게), `store_details` (가게 상세-영업시간 등)
  * 핵심 API: `POST /api/auth/login`, `POST /api/auth/signup`, `GET /api/stores`, `POST /api/stores`
* **FE 개발 범위**:
  * 1️⃣ 로그인 / 회원가입 페이지 (손님/사장님 역할 구분)
  * 2️⃣ 메인 홈 페이지 (카테고리 필터, 가게 카드 그리드)
  * 3️⃣ 사장님의 가게 정보 등록/수정 페이지

---

### 🟡 파트 B: "메뉴판 & 장바구니 주문" (메뉴 & 주문)
* **목표**: 특정 가게의 메뉴를 조회하고 장바구니에 담아 픽업 시간과 함께 주문서를 전송한다.
* **독립 개발 치트키 (Dummy Data)**:
  * `DataInitRunner`에 `가게 1번 (루키즈 베이커리)` 더미 데이터를 사전 세팅하여 A파트 완료 전 독립 개발.
* **BE 개발 범위**:
  * 테이블: `menu_items` (메뉴), `orders` (주문 마스터), `order_items` (주문 상세)
  * 핵심 API: `GET /api/stores/{storeId}/menus`, `POST /api/stores/{storeId}/menus`, `POST /api/orders`
* **FE 개발 범위**:
  * 1️⃣ 가게 상세 및 메뉴판 화면 (`+ 담기` 인터랙션, 메뉴 정보)
  * 2️⃣ 장바구니 & 픽업 시간 선택 주문서 화면 (`주문하기` 완료)
  * 3️⃣ 사장님의 메뉴 등록/수정/품절 스위치 화면

---

### 🔴 파트 C: "실시간 주문 접수 & 매출 대시보드" (주방 & 카운터)
* **목표**: 사장님이 들어온 주문을 보고 `[수락]`, `[조리완료]`를 처리하며 오늘 매출 현황을 확인한다.
* **MVP**: 접수 ➔ 수락(`ACCEPTED`) ➔ 조리완료(`COMPLETED`) 상태 플로우
* **후순위**: 오늘 총매출 통계 조회 (`SUM`, `COUNT`)
* **독립 개발 치트키 (Dummy Data)**:
  * `DataInitRunner`에 `5001번 주문 (바닐라라떼 2잔, 11,000원, 접수대기 상태)` 사전 세팅.
* **BE 개발 범위**:
  * 테이블: `orders` (주문 상태 관리 및 프로젝션 통계)
  * 핵심 API: `GET /api/owner/orders`, `PATCH /api/orders/{orderId}/status`, `GET /api/owner/sales/today`
* **FE 개발 범위**:
  * 1️⃣ 사장님 실시간 주문 접수 대시보드 (`[주문 수락]`, `[조리 완료]` 원클릭 상태 전환)
  * 2️⃣ 오늘의 매출 현황 카드 (오늘 주문 건수 / 총 매출액)
  * 3️⃣ 손님용 내 주문 상태 실시간 확인 화면 (`[조리중 ⏳]`, `[픽업 대기]`)

## 4. 기술 스택 (Tech Stack)

| 구분 | 기술 스택 | 버전 및 비고 |
| :--- | :--- | :--- |
| **Backend** | Java 17, Spring Boot | Spring Data JPA, Spring Security, Validation |
| **Database** | MySQL / H2 (로컬 테스트) | Hibernate, JPA 인덱싱 및 Fetch Join 최적화 |
| **Frontend** | React 19, Vite, JavaScript | Zustand (전역 상태 관리), Axios, React Router v7 |
| **UI / Styling** | Vanilla CSS / CSS Modules | 현대적인 모던 UI 디자인, 다크/라이트 테마 지원 |
| **협업 & 도구** | Git / GitHub, Figma, Postman | 브랜치 분리 전략 (`backend_main`, `frontend_main` 기반) |
